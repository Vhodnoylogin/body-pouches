# CommonLib assessment for synergy implementation

Updated: 25 October 2026. Scope: the second level of the [synergy concept](concept-en.md), moving engine addresses and repeated technical operations behind verified CommonLib interfaces. This is a maintained analysis, not a library implementation task. The technical binding audit below remains pinned to its 11 October source; the new native-placement extraction classification is recorded at the end.

Inspected fork: [Vhodnoylogin/CommonLibSSE-NG](https://github.com/Vhodnoylogin/CommonLibSSE-NG), `ng` at `a898f469851c464d05137bb74b069dd234897643` (9.1.0). Local and remote `ng` matched when inspected. Presence of a declaration establishes an available building block; it does not establish equivalent timing, lifetime or cross-runtime behavior for a proposed use.

## Candidates needing a verified extension or further audit

| Candidate | Why it is a candidate | Evidence needed before implementation |
|---|---|---|
| Copy a named anchor transform relative to an explicitly chosen reference transform without mutating the skeleton | The VRIK adapter walks parent/local transforms and chooses the original holster phase's old-world root transform. Ordinary scene lookup and transform multiplication do not package that whole contract | Check equivalent helper availability across the library; prove root/old-world timing, parent traversal limits and model lifetime. Keep slot binding decisions in VRIK |
| Collector-based world ray query | HIGGS uses a collector overload; CommonLib's `hkpWorld::CastRay` already binds a single-output overload at a different engine address | Adapt the nearest-hit operation after behavior review, or add the specific collector overload with verified signature/mapping. Never reinterpret an output record as a collector |
| Existing linear cast relocation | `hkpWorld::LinearCast` already has the required collectors; its ID60554 is absent from the audited checked-in VR fixture | Verify the current Address Library mapping and native signature. Fixture absence does not establish absence from the installed/current external library |
| World closest-points and penetrations queries | These specific world methods are absent in the inspected checkout; similarly named phantom methods already exist | Verify/add only the required world bindings. A phantom query has different overlap/lifetime semantics and is not a drop-in replacement |
| Listener removal and world listener methods | Entity add/remove bindings exist; current mod removal deliberately nulls a listener slot. World listener methods are not exposed | Verify callback/reentrancy behavior before substituting entity removal; add narrow world operations with their actual lock/lifetime contract |
| Contact separating-velocity fallback | Contact event data already exposes a velocity pointer, but HIGGS also calculates velocity when it is null | Retain the null case and verify only the missing fallback calculation binding/helper |
| Manager-wide ragdoll operations and constraint enable/read | Per-graph ragdoll virtuals and modeled data exist; manager aggregation and constraint enable/read methods are absent | Establish sub-manager traversal, output handling, lock semantics and exact signatures; graph iteration alone is not proven equivalent |
| Ragdoll drive/controller and world entity operations | Driver data exists, but several drive/reset/pose/controller bindings are absent. `RemoveEntity` exists with a return ABI differing from the mod typedef; its VR mapping remains unresolved here | Audit each actual calling convention, result and required minimal type. Do not infer that the existing RE subset replaces the external Havok-like build dependencies |

Only entries explicitly marked absent assert a missing method in this inspected checkout. Other entries concern existing methods whose mapping or behavior needs verification. An extension task should name the precise missing operation established by its library/call-site audit.

The targeted comparison checked current HIGGS and PLANCK engine helpers against this exact library checkout and its checked-in VR mapping fixture. The explicitly absent methods above were searched in both headers and implementations; other entries identify available methods with unresolved mapping or behavior. An address match is source evidence, not an executed engine qualification. Implementation still needs current VR signature/vtable verification and focused lifetime, query, listener and inventory tests. No CommonLib code was changed.

## Keep in the providers

Slot definitions, instance identities and saved overrides belong to Body Slots. Model calibration, inverse kinematics and physical probe interpretation belong to VRIK. Input priority, possession and resource reservations belong to HIGGS. NPC physical behavior and hit-policy decisions belong to PLANCK. Potion choice, proxy policy, harvesting and climbability remain consumer gameplay.

The offline project/package validator and fixed copied ABI contracts have no engine addresses to move into CommonLib. Adopting library helpers inside a game adapter must not make an offline tool require Skyrim or engine initialization.

The new HIGGS restrictions service uses standard fixed-capacity storage, a mutex and a monotonic clock without engine dependencies. Its ownership, legacy-bit composition and world-generation invalidation belong to HIGGS. Only the surrounding engine adapter's world lookup, lock use and collision operations are CommonLib candidates. Body Slots serialization similarly uses the public SKSE interface and explicit portable records; provider/key override ownership remains in Body Slots. Morphbench's authoring mathematics has no runtime engine addresses to relocate.

The native14 placement compatibility bank added on 25 October contains raw copied poses, owner/revision checks and pure transition builders behind one state owner. It adds no engine addresses or CommonLib extension requirement. VRIK's conversion facade still uses its original SDK types, and preserves the legacy raw-versus-clamped-INI distinction. Later CommonLib adoption may use already modeled point/matrix types inside that adapter; it must not normalize the compatibility values or change persistence. Morphbench session recovery similarly belongs to the editor and introduces no engine binding candidate. No CommonLib code was changed by this work.

The native14 policy extraction uses the same private typed state owner as placement, with pure candidates and one commit operation. Its nine-field policy, lease domains, revision checks and INI projection are provider responsibilities; they introduce no engine address or required CommonLib extension. The VRIK adapter deliberately retains the original SDK classes and numerical rules. Existing CommonLib math/string types can be considered during later adapter migration, while controller/haptic execution and slot ownership remain with their providers. No CommonLib implementation was added.

Transient logical equipment instances add bounded identity/revision state, pure transition candidates and composition of existing effective definitions. These stay in Body Slots and introduce no engine addresses or CommonLib extension requirement. The additive VRIK instance view reuses the same anchor resolver and copied transform calculations already assessed above; optional-service buffers and freshness checks are adapter ownership/lifetime work. Actual equipment-model binding has not been added, so this checkpoint claims no new qualified engine lookup. CommonLib remains unchanged.

Saved per-instance placement adds a portable bounded codec and coherent two-store SKSE serialization batch. Stable-key ownership, customization precedence, dormant records and scope/view comparison remain Body Slots policy. This uses the already public SKSE callbacks and standard byte/copy operations; it creates no engine address or necessary CommonLib extension. The new VRIK final-instance geometry view shares the existing copied transform path and freshness checks. Equipment-model lookup is still unimplemented and therefore not presented as qualified CommonLib reuse. No library code changed.

Morphbench local placement variants reuse pure copied composition and explicit geometry overrides; versioned editor recovery and unbound preset formatting remain editor responsibilities. They do not read or change game state and introduce no address handling or CommonLib extension requirement. A preset is not a serialized runtime instance or a substitute for provider-owned equipment identity.
