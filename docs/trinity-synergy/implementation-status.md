### Published PLANCK services

The original 001 API is preserved. Revision 2 supplies copied actor/body observations, owned generation-checked endpoints, removable subscriptions and precommit physical-hit policies. Native graph/world publication precedes observer dispatch. Melee supports veto, while clutter also supports bounded damage scaling; neither notification proves post-mitigation health loss.

Direct-capsule proposals now use fresh live-body resolution under graph/world write ownership, private engine-cloned shape wrappers and retained native bodies. Shared authored capsules stay unchanged. A deferred shape setter remains pending until the exact clone is observed on that body; accepted work cannot be released early. Entity removal retires wrapper back-pointers and references. This fixes the earlier unavailable geometry executor, but does not yet edit PPB's compound list children.

A separate native bridge lets HIGGS independently acquire an endpoint and visit its freshly resolved body/world within a borrowed, synchronous scope. It forbids retaining borrowed pointers or taking further graph/world locks. HIGGS owns any resulting physical constraint and its invalidation response.

A separate drive API applies actor-generation-scoped pivot restrictions, selected hierarchy/velocity/position gains and body weights around PLANCK's existing controller call. Public palette mapping determines each body's effective fraction; weights are capped to avoid target extrapolation. RAII restores exactly the changed fields/pointer, including exception exits. Numerical policies have explicit exclusive ownership; pivot-only restrictions compose. Already-loosened pivots restore without subsequent blocked interpolation writing them back. Copied results describe an actual driver observation, not PPB's complete pose solver.

The current PLANCK DLL is 836608 bytes, SHA-256 `5f1f0c4c2f890c7a541dd8b06e573e10270990ae63bdc4a7ab91e582d36719cd`. Its 47 native source/build input pins were verified before publication. Standalone C/production-core and extracted-native fixtures pass, including deferred geometry, exact endpoint ownership, drive composition, stale public/private palette mappings, pivot restoration and callback/lifecycle cases. Two drive negative controls, 78 reset-cleanup checks and three cleanup negative controls pass. Independent review verified the two drive corrections. These are source/native checks, not game qualification.

### HIGGS working-tree services under completion

The broker remains the single owner of hand grants, input arbitration and action receipts. New typed transactions add correlated exact original/proxy/display item identities, item locks, bounded idempotency history, one-shot native mutation permits, observed physical release/grip and explicit compensation/recovery. Equipment admission and observed equipment completion are distinct. A registered executor alone is insufficient for ordinary inventory handling: a shared native inventory/equipment backend is still being implemented, so common transfers are not claimed complete.

Finite sessions support contact/pose/activation-driven interaction without inventing a button press. General OpenVR input observations and bounded hold/multi-tap routing extend the legacy grip/trigger path while preserving it. The actual controller callback has source-backed tests; system/proximity remain observation-only. Consuming the raw trigger is not equivalent to the narrow draw-only policy needed by Stop Trigger Unsheathing.

Copied motion/contact/release observations carry sample provenance, explicit units and lifecycle checks. Haptics use HIGGS's existing hardware scheduling path. Moving-world support, PLANCK-owned NPC endpoints and held-item constraints have actual native adapters and extracted-source fixtures. Capabilities remain conditional on the installed driver/PLANCK interfaces; an unimplemented player-weapon support kind is not advertised.

A synchronous authorized-mutation fence rechecks grant/epoch/assigned action on the observed main thread, commits the receipt before ending the fence and defers conflicting lifecycle reset until the admitted mutation returns. Body Slots uses this for persistent drag placement rather than a racy copied-permission check. Final integrated independent review and stable source-pinned builds remain pending.

The complete HIGGS native DLL has linked with the new services during development; later source edits require rebuilding. Passing a manifest while its dependency files changed is explicitly rejected by the Body Slots build tool. Articulated PPB finger boxes, further scoped physical-property/grab/presentation policies and the native inventory backend are still active implementation work. Do not infer that a successful earlier build includes those later changes.

### Body Slots working-tree extensions

The independent runtime owns slot definitions/instances, entry/exit/hover/invalidation, immutable offers, exclusive reservations, selected provider dispatch, confirmed-content mirrors and holder/preview presentation. Current extensions add capsule and oriented-box containment, atomic equipment-provided slot sets, saved form/keyword/form-list content filters, explicit none/HIGGS-held/game-equipped source selection and an armed drag customizer. Drag persistence commits under the HIGGS mutation fence and explicitly releases its grant after completion/cancellation.

Saved binding/visual/policy records use stable keys and a versioned portable codec; old record versions remain readable. Form remapping and full-batch decode precede publication. Missing equipment, ambiguous/replaced nodes or unresolved policy forms remain dormant. Engine content evidence is gathered at the main phase and matched to the HIGGS observation. Runtime grants, callback pointers and activation are not serialized. No VRIK reconstruction is required.

Production extension checks pass, and native build, combined HIGGS/Body Slots protocol tests and DLL negotiation have passed on intermediate inputs. The latest combined build was correctly refused as final evidence because a HIGGS source file changed during it. A final stable closure build is outstanding. The runtime still has one behavior per instance; other probe kinds are point-query services rather than automatically sampled activation probes. Reusable ordinary inventory handlers, native-14 assignment migration and actual asset/pose/input/save-load behavior still need completion or qualification.

### PPB research and consumer coverage

The [twenty-consumer matrix](consumer-contract-matrix.md) tests a diverse sample of interactions; the target remains any Skyrim VR mod, not those twenty names alone. No sampled consumer has been migrated and game-qualified by this delivery. A capability must offer a practical shared operation, not merely ask each consumer to register its own replacement mechanic. Domain policy, crime, harvesting rules, projectile flight and anatomy stay with the appropriate consumer/provider.

PPB requires eight independently tracked player finger boxes plus the HIGGS palm, and capsule children in existing NPC list shapes. Whole-hand extents and direct-capsule adoption do not replace these. Its anatomical API also needs coherent revisioned geometry, removable/drainable subscriptions, explicit lifetime endings and coverage negotiation. Player-self target coverage is not established. The requests for telord separate independently useful PPB API improvements from integration that first requires services and qualification on our side. They have not been sent.

## Still required

These remain concept requirements; implementation is paused under the owner's current priority order. The current private one-unique-ARMO/native13 demonstration has an offline checked implementation; it is not game qualified or a delivered implementation of the generic requirements below.

- Actual equipment identity/restoration by a consumer, equipment-model binding, content/visual descriptors and preview lifecycle. Logical instances and separate saved per-instance placement are delivered; activation and live handles remain transient.
- Native14 runtime saved-array and full Papyrus/game regression coverage beyond the delivered placement/policy configuration facades. The original global INI semantics must remain distinct from generic save-scoped customization.
- Independent Body Slots spatial interaction, binding, feedback, behavior dispatch and presentation for new slots, with a qualified body/hand pose adapter and tracking/model/handedness validation. Geometry alone cannot draw, deposit or display an item.
- HIGGS's authoritative closed occupancy/availability model, shared hand-use primitives including world-support grip, input arbitration, exclusive physical resource ownership, coherent possession and correlated transfer outcomes. Temporary restrictions can coexist; they do not arbitrate an exclusive action or detect hidden private mod state.
- PLANCK's `DropObject` currently uses legacy `DisableHand` to end an established hold. New admission restrictions preserve that hold; this consumer needs explicit release with a correlated result before changing that call.
- Transfer cancellation across both hands: cancelling a receiver's pending pull cannot undo a donor release queued before a new restriction. A correlated transaction must cover that earlier side effect.
- PLANCK copied actor endpoints, generation-aware attachment requests and bounded hit-policy participation.
- Consumer migrations and Skyrim testing, including real anchors, loading, inventory-to-grip commitment and original14 regression coverage.

## Current internal audit follow-up

The source-backed HIGGS/PLANCK audit remains recorded for later author discussion; further implementation goals are explicitly deferred by the owner.

Current PLANCK already restores pending ragdoll constraints on removal; the earlier premise that restoration was missing is obsolete. Remaining source-backed cases need a larger lifetime contract: tracking can remain active after the animation graph/world disappears, deferred furniture cleanup now rejects work crossing `ResetObjects`, but same-epoch actor/graph changes remain unguarded, and legacy per-actor overrides retain raw actor keys. Counterexamples establish the conditional control-flow gaps, not their frequency or harm in Skyrim. New actor endpoints and queued actions must validate generation and ownership instead of dereferencing saved driver pointers. Constraint-snapshot restoration also performs repeated membership searches; its performance importance needs measurement before optimization.

HIGGS development now repairs the observed-failure history retention found in `FillControllerVelocities`. Invalid callbacks and world/load changes clear the relevant histories; copied availability gates low-speed and directional decisions, and controller-only release contributions become zero without removing player/object motion. A source-level ordering counterexample also prompted monotonic observation tickets: an older valid calculation cannot overwrite a newer invalid observation, even at equal clock times. The separate [velocity ABI](https://github.com/Vhodnoylogin/higgs/blob/development/docs/velocity-observation.md) now exposes source, producer-computed age, space, units and factual history count from that same owner. Consumers still require an explicit age policy. This remains an observation service: hardware tracking, current palm/pose, tracking-to-world continuity, actual dropout behavior and engine scheduling remain unqualified. VRIK's node/finite-position proxy cannot substitute for those facts.
