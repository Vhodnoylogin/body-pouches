# Synergy implementation status

Updated: 11 November 2026. This ledger accompanies the [English concept](concept-en.md) and [Russian concept](concept-ru.md). The concept describes the target architecture; source implementation, native linking, consumer adoption and running-game acceptance are separate evidence levels.

It invalidates old observations on save, model, cell or physics-world replacement. The region registry reuses batch storage and publishes validated observations atomically. Its SDK composes the two upstream proposals in an [NPC pocket example](https://github.com/Vhodnoylogin/body-slots/blob/9e3273938725cb35edca04b9283dc9bd45363c5a/docs/planck-pose-region-anchor.md). Offline, an eligible left-hand press activated once. Replacing the pelvis body before execution cancelled the selection. The native Body Slots DLL passed its export/negotiation probe and all 13 CTest programs passed. A combined native-source fixture exercised HIGGS arbitration, PLANCK body lookup/removal and the Body Slots registry with simulated game inputs. No gameplay acceptance or new end-user release follows from these checks.

[Body Slots candidate source](https://github.com/Vhodnoylogin/body-slots/tree/b4db42ab1d2eb96ab0c7286ba06ad08601729cbd) includes the MIT license for its own code and SDK. The unpublished 0.2.0-rc.1 runtime retains the November 3 DLL. Both candidate archives reproduced byte-for-byte and the extracted SDK examples compiled. An optional consumer example reads the exact PLANCK sample time and invalidates its logical anchor on replacement or stale input. The runtime was also rebuilt against the HIGGS upstream proposal, passing all ten existing CTest targets and native-DLL discovery offline. The candidate has no in-game qualification.

**Audit result.** A pouch opening is a logical region even when no physical body exists there. A PPB capsule can be touched when no mod offers an action. A PLANCK hit can occur without a new grip press. These cases justify three independent observations. A grant from HIGGS authorizes an attempt, while the mod that changes inventory must confirm the actual transfer. Inferring transfer from a callback return would let a potion disappear or be credited twice on failure. A feature that only reads a pose or contact has no need to register an input executor. Grouping every optional operation into a mandatory first handshake would impose costs on unrelated consumers. Upstream acceptance and live gameplay verification remain open.

The VRIK proposal in both concepts now uses one read of multiple named anchors from the same final pose. This design uses the existing SKSE discovery pattern and keeps the published 001 interface intact. It is an independent design proposal with no new VRIK build or author agreement.

## Interaction regions and slots

The owner accepted the region/slot standard after the [twenty-consumer investigation](../trinity-research/interaction-regions-review-ru.md). Both concepts now define a slot as a named interaction region with offered actions and activation rules. Storage, presentation and persistence are optional. Body Slots owns logical spatial evaluation and slot mechanics; HIGGS owns hand state/use, input, grants and physical operations; VRIK supplies body/virtual-hand poses; PPB supplies anatomical geometry/fitting/query evidence; PLANCK owns NPC physics, physical contacts and hits. Consumer gameplay remains external.

[Body Slots development source](https://github.com/Vhodnoylogin/body-slots/tree/feature/extract-body-slots) implements the first additive [interaction-regions table](https://github.com/Vhodnoylogin/body-slots/blob/feature/extract-body-slots/docs/interaction-regions.md), with unchanged layouts for older negotiated tables:

- Live-writer-owned named regions with exact revisions, copied snapshots and bounded atomic publication.
- Player/NPC/world/transient anchor kinds; externally supplied anchor and point-probe observations with declared provider/source/target identity, frame, time, units and generations.
- Shared sphere/capsule/box/finite-cylinder geometry; flat endcaps, proper rigid transforms and positive uniform scale. Existing saved slot shapes also support cylinders through an advertised capability.
- Separate entry/exit hysteresis and spatial dwell, with explicit monotonic time and continuity limits.
- Missing, stale, incoherent or repeated samples are unavailable. Generation changes, omissions, rollback, runtime invalidation and save changes break dwell.
- Copied last-evaluated observations, including spatial readiness. They do not authenticate external providers, establish present freshness, create physical contacts or grant hand authority.

Independent review reproduced and verified repairs for two defects: a direct save reset preserving old readiness, and pruning a live writer during a failed release. The registry owns actual save generation and lease existence; the region service observes them through narrow private getters. Runtime scope acceptance and invalidation use the same runtime lock. The simultaneous scheduling case was reviewed in source; the two concrete reset/release counterexamples were independently replayed.

## Arbitrary region actions through HIGGS

The additive Body Slots [region-action table](https://github.com/Vhodnoylogin/body-slots/blob/feature/extract-body-slots/docs/region-actions.md) now binds owned named regions to the shared HIGGS recognizer, provider priorities and selected execution route. A consumer supplies copied target anchors, pure action proposals and its gameplay handler. Body Slots supplies the actual HIGGS palm probe, spatial readiness and contextual revalidation; the consumer needs no separate grip/trigger hook. Existing player-slot behavior/content routes remain supported.

The consumer explicitly delegates its HIGGS client for a per-binding executor. The independent Body Slots recognizer submits routed candidates; HIGGS retains the user's effective provider priority and sole winning grant. Body Slots checks current region revision, target identity/generation, geometry, source time, save/epoch, actual held/equipped state and every required hand before the handler. Moving samples of the same target are re-evaluated rather than treated as a rebind. Target and palm retain their actual independent source frames and bounded age/skew. No caller-provided point is accepted as the authoritative hand probe.

HIGGS's separately negotiated [authorized-dispatch service](https://github.com/Vhodnoylogin/higgs/blob/development/docs/authorized-dispatch.md) invokes the deferred handler under the existing main-phase authority fence and claims the request once before entry. Callback success, failure and exception create no inventory/commit/completion receipt. Body Slots does not retry another action or infer cancellation/noncommit after an arbitrary handler was entered. Consumers retain their actual HIGGS physical/transaction outcomes and report factual parent results after dispatch. The existing consumed Down/Up sequence prevents an unrelated second action from claiming the matching release.

This connection is negotiated before the VRIK-backed player-slot adapter and does not use the native mouth/stash detector as a second executor. HIGGS keeps its standalone behavior when Body Slots is absent. Immediate grip/trigger edges are supported here; deferred gestures, nonbutton offers, consumed-press continuation, provider authentication and full consumer ports remain separate capabilities. A legacy mod that independently hooks raw controller input is not automatically enrolled in this coordination.

## Native mouth/stash verification

The preceding bounded integration connects HIGGS's actual native mouth and shoulder inventory-stash source frames to Body Slots. HIGGS exposes an additive optional spatial-detector table; Body Slots negotiates it at runtime and owns the registered region checks. No Body Slots startup/link dependency is added to HIGGS, and the spatial connection does not require the VRIK-backed player-slot adapter. Missing or incompatible services select HIGGS's native fallback. A valid handled result, including outside/unavailable zero, does not invoke that fallback. HIGGS keeps eligibility, velocity gates, hand authority and the sole consume/stash/drop executor. Transactional physical release still suppresses auto-consumption/stash.

Published source: [HIGGS `3deb5bf`](https://github.com/Vhodnoylogin/higgs/commit/3deb5bfbcfe1c40d8b2318bc331f5121eefaf399) and [Body Slots `c1b38fc`](https://github.com/Vhodnoylogin/body-slots/commit/c1b38fcf6b161f5b8ba2e68e8c98ab47131f4bd1). Their [HIGGS contract](https://github.com/Vhodnoylogin/higgs/blob/development/docs/native-regions.md) and [Body Slots adapter](https://github.com/Vhodnoylogin/body-slots/blob/feature/extract-body-slots/docs/higgs-native-regions.md) describe the implemented boundary.

The copied frame uses current native HMD/hand/palm/configuration inputs, not an older post-VRIK observation. It declares epoch, monotonic sample/time, hand generation and a private source generation that changes for HMD replacement, geometry configuration and scale reinterpretation. Body Slots publishes three transient regions per physical-hand stream, preserves other-hand observations, disables only individual nonpositive-radius regions, rejects replay/regression and resets across saves. Spatial readiness is not a generic action offer or a confirmed inventory receipt. Its strict double-precision boundary is not bit-identical to the old float calculation near rounding boundaries.

Native action admission refreshes through the selected detector and checks current HIGGS authority. Requested-event callbacks are followed by another refresh/fence before the game write. Rejection becomes ordinary drop without retrying another slot. Physical/operation grant creation shares the native-phase gate; callback removal/unregister uses HIGGS's existing ownership and drainage rules. These changes implement a narrow native consumer integration, not the whole generic region action architecture.

Both new full native DLLs build. ## Remaining integration work

The spatial service evaluates supplied points against finite primitives. The optional native HIGGS mouth/stash integration and arbitrary region-action route above are implemented in the cooperation sources, with game qualification pending. General capability-bound source registration, PPB/PLANCK source adapters, anatomical surfaces, rays/sweeps and composite shapes remain unimplemented. Existing player-slot activation continues through its existing HIGGS route. Pickpocketing and the other consumers have not been ported; generic regions have no separate content, presentation or persistence subsystem.

Next: connect and qualify a concrete consumer through the region-action route, and qualify the native HIGGS/Body Slots integration through the testing workflow. The native spatial callback and generic action table have distinct roles; neither establishes a consumer port or running-game acceptance. Keep PPB anatomy and PLANCK/HIGGS physical bodies under their current owners. Original-shield/effective-equipment transitions, full consumed-draw release continuation and other domain executors remain separate unfinished work.
